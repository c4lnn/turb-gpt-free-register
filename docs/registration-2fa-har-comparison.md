# HAR、本地仓库与 OSS 注册及 2FA 逐端点对照

## 范围与证据约定

本文把两份独立捕获分别展开；不把不同账号、session 或分支拼成一条链。每个端点固定列出 HAR、本地仓库、OSS、差异。HAR 序号按各自文件内顺序；本地代码是当前工作区，OSS 是 `../turb-gpt-free-register-oss-20260928/` 固定快照。文中 OSS `协议/...` 路径相对于该快照的 `vendor/gpt-register-tool/`。

- HAR A：`har/passwordless2about-you.har`，2026-11-01 19:14:05–19:15:48 UTC，83 entries。捕获 signin 返回的 authorize URL、passwordless OTP、注册、OTP 验证；未捕获 profile、callback/session、注册后 2FA。
- HAR B：`har/11.1-密码注册-快路径设置2fa.har`，2026-11-01 16:22:53–16:24:26 UTC，815 entries。从 `GET /create-account` 开始，捕获注册、OTP、profile、callback/session 和 MFA 快路径；未捕获进入该 HAR 前的 signin。
- 表中只列与注册 / OTP / Sentinel / session / MFA 相关的请求。HAR 未记录、源码未显式构造、条件性请求未触发、没有对应实现，分别按这些证据状态陈述；静态头构造不等同于最终 wire headers。
- Cookie、Bearer、Sentinel token、OTP、邮箱、密码、session ID、设备 ID、TOTP secret 和动态 query 值均不复述。响应只列与流程判断相关的字段。

### 端点层面的结论

- HAR A 是 passwordless OTP 分支；HAR B 是密码注册并成功启用 TOTP 的独立捕获。它们不是同一个账号或连续 session。
- Auth JSON POST 逐端点的关键差异是 Referer、Origin、Sentinel 主 / SO token、追踪 / invocation / navigation IDs；ChatGPT MFA API 另有 Bearer、设备 / 客户端头、`source=settings` 与额外 factor-decision 请求差异。上表只把 HAR 实际记录的头与代码显式构造分别列出。
- 本地注册 TOTP 由 `ENABLE_2FA` 控制，默认配置为关闭；HAR B 记录的是已启用分支。未触发的配置分支不视为“没有实现”。
- 固定 OSS 快照的注册、callback/session 与 MFA 细节见[注册与 2FA OSS 源码对照](registration-2fa-oss-comparison.md)。本文不证明服务端接受任何未实测的候选差异，也不包含真实账号 smoke。

**敏感数据提示：**本地注册日志可能记录密码候选与 TOTP secret；HAR 和日志均按凭据材料保护。
