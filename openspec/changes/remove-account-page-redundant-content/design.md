# Design

## Context

参见 `proposal.md` 的 Why。当前控制台在 `App.tsx` 为所有标签共用页面说明和资源概览区；账号模块自身又在 `AccountsPage.tsx` 渲染一次标题与说明。变更须只调整账号管理页的呈现，不影响其他标签或账号操作。

## Goals / Non-Goals

**Goals:**
- 让账号管理页从主标题与自动刷新状态直接进入已注册账号内容卡片。
- 保持其他控制台页面现有的页面说明与资源概览。

**Non-Goals:**
- 不更改资源概览数据获取、API、账号数据或列表功能。
- 不调整其他页面的内容或全局布局样式。

## Decisions

- 在共享页面壳层按当前标签决定是否渲染页面说明和资源概览：账号管理页不渲染，其他标签继续渲染。相比全局删除，这能遵循仅针对截图中账号页冗余内容的范围。
- 从账号页面组件中移除重复的标题和说明容器；保留错误提示、操作提示以及“已注册账号”卡片及其内部功能。相比隐藏整块账号组件，这不会影响账号管理操作。
- 不新增 CSS 或运行时开关；用页面现有标签状态控制显示，避免维护第二套页面状态。

## Risks / Trade-offs

- [条件遗漏] 若只隐藏页面说明而漏掉资源概览，账号页仍保留截图中的冗余区域 → 同一条件同时控制说明与概览，并核对账号页与其他标签。
- [标题层级变化] 移除账号组件内标题后，页面主标题成为唯一账号管理标题 → 保留“已注册账号”卡片标题作为列表区标题。

## Migration Plan

无需数据迁移或服务端变更。构建前端后部署静态资源即可；回滚时恢复两个组件中的呈现条件与标题区。
