# Proposal

## Why

现有 SAZ 分析只覆盖登录主线与部分差异，无法逐条查阅三类共 17 条请求的完整头字段、请求体、Cookie 组成及字段来源。需要一份可回溯原始捕获、区分观测事实与来源推断、且不扩散凭据的详细报告，作为后续协议讨论的依据。

## What Changes

- 新增单份报告 `saz/login-password-totp-403-request-details.md`，唯一捕获输入为 `saz/login-password-totp-403.saz`。
- 按捕获序号逐条展开 #11、#15、#16、#17、#18、#19、#26、#27、#28、#32、#34、#58、#84、#87、#89、#93、#98；每条具有独立表格，不合并相同端点或重复 SDK 请求。
- 每条记录方法、域名与路径、全部 query 字段、全部请求头、请求体结构与字段，以及逐项 Cookie 组成；无请求体、空值、字段缺失分别说明。
- 每条表格后逐字段解释来源，以捕获响应与请求的内容匹配、明确源码赋值或调用作为证据；无法证明的来源明确写“无法判断”。本地构造仅作辅助说明，不替代捕获事实。
- 非敏感字段保留实际值；凭据及动态敏感标识使用稳定占位符，保留结构、字段存在性与跨请求相等关系，不生成原值映射文件。
- 报告开头限定捕获范围与认证比较截止点；其他类别仅在必要时作为字段来源证据引用，不扩展审计。

## Capabilities

### New Capabilities

无。本次仅增加一次性捕获分析文档，不增加系统行为；依 schema 使用 `skip_specs: true`，不创建 `specs/saz-request-documentation/spec.md`。

### Modified Capabilities

无。不改变注册、登录、查活、Sentinel、MFA 或套餐查询的任何协议行为。

## Impact

- 规划文件：本变更的元数据、proposal、design、tasks。
- 后续 apply 的唯一永久交付文件：`saz/login-password-totp-403-request-details.md`。
- 原始 SAZ、现有分析文件、运行配置、源码、测试和依赖均不修改；不重放网络请求，不提交或推送抓包与报告。
- 验收聚焦 17 个独立请求段落、完整字段覆盖、来源证据、正确区分未知与缺失、以及敏感值不泄露，不依赖构建或运行项目。
