# Design

## Context

动机与输出范围见 `proposal.md`。输入 SAZ 以 `raw/<序号>_c.txt`、`raw/<序号>_s.txt` 保存请求与响应，包含真实凭据。已有分析不能替代原始报文。报告正文需要完整枚举，但字段值相等、传递来源、浏览器内部生成算法是不同层次的结论。

本设计处理敏感信息和来源归因的复杂性，满足 schema 的 design 创建条件；变更不改变系统行为，因此跳过 specs。

## Goals / Non-Goals

**Goals:**

- 将每个入选请求作为独立可检索单元，字段覆盖可以逐项对照原始捕获验收。
- 不输出原始敏感值的前提下，保留跨请求传递和变化所需信息。
- 将捕获观察、响应来源证据、本地源码构造与无法判断严格分开。

**Non-Goals:**

- 不修改协议实现，不新增永久解析工具、依赖或自动化测试。
- 不重放请求，不补造捕获外的成功登录、注册或 SDK 消费者。
- 不逐端点重新审计已确认顺序，不评判未实测差异是否被服务端接受。
- 不复制响应全文、混淆 SDK 的 JS 环境与 HTTP 头画像，也不反推传输层指纹。

## Decisions

### 1. 固定 17 个请求与单份报告，不按端点合并

请求集合为 #11、#15、#16、#17、#18、#19、#26、#27、#28、#32、#34、#58、#84、#87、#89、#93、#98，正文按序号升序排列，保留所属三类标签。

报告开头声明：捕获为已有账号的密码与 TOTP 登录；认证比较截止 #93 MFA verify 的 403 响应，后续选中辅助流量仍列到 #98；未记录成功回调及最终 session 获取。范围外请求只为字段来源提供最小证据，并标为“辅助请求”，不计入 17 个独立段落。

每个请求保留独立段落，但相同字段和值提取到具名公共表；本条通过明确的字段组引用与增补／覆盖还原完整内容，避免重复列出 UA、语言、Client Hints 与相同 Cookie。不能仅因端点相同合并请求，#27/#32 的发起上下文及 #58/#84/#93 的 token、Accept 差异必须保留。

### 2. 每条独立表格，随后逐字段来源说明

每个请求段落包含方法、host、path、对应 SAZ 成员名，以及一张四列表格：

`位置｜字段／公共组｜捕获值或引用（敏感项占位）｜说明`

表格分区包含：

- query：保持字段及重复项；query 内嵌 URL 继续列其子字段，敏感值不能通过 URL 编码绕过脱敏。
- headers：先引用具名公共字段组，再列本条新增／覆盖；展开后必须与原始全部头字段名和值一致（头名忽略大小写）。简化展示不保留原始头排列，原序查 SAZ，不以顺序变化推断行为。不存在的字段不得从组中引入。
- body：记录是否存在、原始 Content-Type、实际结构、全部字段路径与类型、固定值、空串和 null。表单保留编码规则和重复键；JSON 文本保持实际传输类型，不能因为可解析为 JSON 就改写为 `application/json`。原始长度与占位展示长度区分，不能按脱敏后的字符串重算捕获 Content-Length。
- Cookie：按域名提取完整的名称／占位值基线；本条引用基线并显式列出值变化、新增或删除。展开后名称和值必须与原始请求一致，名称集合相同不代表值相同；原始项序与重复项查 SAZ。Cookie 请求头不含 Domain、Path、HttpOnly、SameSite 等属性；仅在匹配到 Set-Cookie 时说明，不得补造。

无 query 或 body 显式写“无”；字段缺失与空值分开。每张表后按字段组解释来源，共用机制只说明一次；响应匹配与本条特有差异就近列出证据。query／复合 token 等相同结构也可提取具名组，但必须明确适用请求和实际占位值，确保展开覆盖全部输入。

### 3. 来源结论分层，禁止以同名／相邻代替证据

每个字段使用以下证据口径：

- **捕获事实**：仅陈述实际值、字段集合、相等或变化，不称为已证明生成来源。
- **响应到请求匹配**：注明前序请求序号、响应字段或 Set-Cookie 名称、当前请求位置及匹配结果。无法精确匹配时明确不成立或无法判断。
- **本地源码构造**：仅在解释来源确有帮助时引用当前赋值／调用路径和行号，注明是本地规则而非浏览器内部证据；不得把源码构造称为最终 wire headers。
- **无法判断**：捕获缺少生产者、存在多个可能生产者、只能观察到静态结果，或涉及浏览器内部随机源、画像选择、时区及 JS 运行时算法时明确标记。

覆盖 UA / Client Hints、Accept 系列、Content-Type/Length、Host/Connection、缓存和条件缓存头、Origin/Referer、Fetch Metadata、CSRF、OAuth state/PKCE、设备及 auth-session logging 标识、document-navigation/invocation ID、trace/RUM、Sentinel、Cookie，以及 query/body 的所有输入。未出现的字段不编造来源；时区等仅在实际报文或相关结构中出现时展开。报告附一处字段缺失说明区分“SAZ 未记录”“本地未显式构造”“条件分支未触发”“无对应实现”和“无法判断”。

Sentinel 仅对已匹配的 #34 → #58（password_verify）和 #87 → #93（verify_mfa）展开 challenge 到消费者的关系，apply 时重新核对内容。#89、#98 仍独立列完整请求字段，但不扩展无匹配 challenge，不声称其未被消费。SO 元数据不当作 SO token；`p` 等编码字段可说明可验证结构与输入类型，内部凭据／标识仍脱敏，不能宣称还原 SDK 算法。

### 4. 稳定占位符保留关系，不建立明文副本

采用不含真实值或其片段的顺序标签，例如 `<device-id-1>`、`<csrf-token-1>`、`<cookie-value-1>`。同一捕获内经原文比较确认相同的值复用标签，不同值分配新标签；需要展示编码／包装后的对应关系时说明“解码后匹配”，不伪称原始字节相同。复合 token、内嵌 JSON、URL、Base64、Referer query 均先在内存解析后脱敏；无法安全细分的 opaque 值整体占位，并明确内部结构无法判断。不得以不可逆摘要替代密码等低熵秘密的脱敏。

密码、邮箱、OTP、Cookie 值、Bearer/JWT/Sentinel token、CSRF、OAuth state/PKCE、设备／会话标识、trace/invocation/navigation ID 和动态敏感 query 均不进入报告、规划文件、日志或临时文件。非敏感固定值按捕获保留。内存中的值比较仅用于形成占位关系和证据，不输出映射。

原始 SAZ 保持原状且不加入提交；脱敏报告也不自动提交或推送。

### 5. 一次性离线提取和针对性交付验收

后续 apply 只使用离线读取，不创建通用框架。可使用不落盘的临时命令提取结构、内存比较响应和请求，输出必须已脱敏。除最终 Markdown 外不保留辅助文件。

验收核对 17 个序号各有一个主请求段落、独立表格及后置来源说明；展开公共头组、query／token 组和 Cookie 基线加本条差异后，与原始 query/headers/body/Cookie 的字段和值逐项一致。简化仅改变呈现，不丢失空值、缺失或动态值变化。重点保留 #15/#16 同头、#17 表单、#18/#19 跨站导航、#84 无 token 且 Accept 为 */*、#27/#32 发起上下文不同，以及 Sentinel POST 的 text/plain 与低熵 hints。

最后离线检查原始敏感值未泄露（包括常见编码或复合字段内的暴露），只输出通过状态与计数，不输出命中原文。只检查本次报告，不运行构建或项目测试，不发网络请求。

## Risks / Trade-offs

- [捕获只反映一次失败登录] → 明确截止点，不推断成功分支，也不推广为浏览器固定规则。
- [静态值相同被误写为来源一致] → 独立记录值比较和来源证明，缺证据直接写“无法判断”。
- [编码字段或 Cookie 包含嵌套秘密] → 解析后递归脱敏，opaque 值整体占位，验收检查常见编码形式。
- [完整枚举导致重复篇幅] → 公共组保存相同字段和值，17 条独立表格只列引用与差异，以展开等价检查保证不漏字段。
- [脱敏后无法按报告复现原始字节] → 保留原始长度、类型、编码及关系说明；报告定位为分析证据索引，不是可重放报文。

## Migration Plan

无部署、迁移或兼容性变化。apply 阶段仅新增报告；若需撤回，删除本次新增报告即可，原始 SAZ 与现有分析不变。规划完成不代表已完成报告或其验收。
